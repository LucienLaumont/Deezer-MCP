Ce que le serveur sait faire

Chaque tool renvoie des champs propres — jamais la réponse brute de l'API. Les résultats ci-dessous sont de vraies réponses du serveur.

search_artists Recherche

Renvoie le nombre de fans de chaque candidat, ce qui permet de trancher entre homonymes — même quand la requête est mal orthographiée.

search_artists("kavinski")
Kavinski 46
Kavinsky 495 119
Mavins 27 928

L'homonyme à 46 fans sort avant le vrai Kavinsky dans le tri Deezer.

search_tracks Recherche

Des titres par texte libre. Piège documenté : chercher un artiste peut remonter des morceaux où il n'est que featuring.

search_tracks("Stromae", limit=3)
1 des fleurs x stromaeTove Lo — pas un titre de Stromae 2:52 2 Alors on danseStromae · Cheese 3:28 3 Ma Meilleure EnnemieStromae · Arcane 2:27
search_albums Recherche

Des albums par titre ou par artiste, avec le nombre de pistes — de quoi distinguer une réédition de l'album d'origine.

search_albums("Random Access Memories")

Le brancher sur ton client

Le serveur est déjà déployé. Rien à installer : il suffit de le déclarer.

.mcp.json 
{
  "mcpServers": {
    "deezer": {
      "type": "http",
      "url": "https://deezer-mcp.onrender.com/mcp"
    }
  }
}
  1. Déclarer le serveur Colle ce bloc dans le .mcp.json de ton projet, ou ajoute le connecteur distant depuis les réglages de ton client.
  2. Redémarrer le client Les 9 tools apparaissent dans la liste des outils disponibles.
  3. Demander quelque chose « Fais-moi une fiche sur Kavinsky » ou « une playlist electro pour coder ».
Hébergé sur une instance gratuite qui se met en veille après inactivité : le tout premier appel peut prendre une trentaine de secondes. Les suivants sont immédiats.
