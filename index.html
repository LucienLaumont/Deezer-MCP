Deezer MCP

Un serveur Model Context Protocol qui ouvre le catalogue Deezer aux assistants comme Claude — recherche, previews audio, fiche artiste composite et playlists générées par ambiance.

Une vraie session Claude, tapée en direct et sans scénario : une découverte d'artiste, puis une sélection construite à partir d'artistes similaires.

tool composite

Enchaîne trois endpoints côté serveur pour n'exposer qu'un seul appel au modèle, et résout un nom d'artiste vers le candidat le plus populaire — le classement par pertinence de l'API ne suffit pas à retrouver l'artiste réellement recherché.

Playlist par ambiance

l'intelligence reste côté modèle

Aucune analyse de langage côté serveur : ces deux tools fournissent la matière première (genres, charts) pour que le modèle compose lui-même une sélection cohérente avec une description libre — « ambiance road trip de nuit », « énergique pour courir »…

list_genres()Genres disponibles, pour cibler un chart
get_chart_tracks(genre_id, limit)Titres populaires du moment, globalement ou par genre
Ingénierie

Sous le capot

Les décisions qu'une démo ne montre pas, mais qui tiennent le serveur debout.

Des erreurs en HTTP 200

L'API répond 200 même en cas d'erreur logique. Chaque requête vérifie donc la clé error du payload au lieu de se fier au code de statut.

Popularité plutôt que pertinence

Chercher « Justice » par nom peut renvoyer un homonyme à 1 000 fans avant le groupe à 800 000. La résolution retient le plus fort nb_fan, pas le premier résultat.

32 tests, zéro réseau réel

Suite pytest avec respx branché au niveau du transport httpx — mise en forme, gestion d'erreur et tools composites couverts sans dépendre du réseau.

CI sur chaque push

GitHub Actions enchaîne ruff check, ruff format --check puis pytest, à chaque push et pull request sur main.
